# Security red-team report: the Studio, 2026-11-13

Reviewer: the security attacker (one of the three red-team reviewers in CLAUDE.md rule 12). I received the code and the running app, not the builder's conclusions.

## Result in plain words

I found **no way to run script** in the Studio or inside a Mockup preview, **no way to change the Studio's page structure** from project data, and **no way to make the page send data anywhere**. The escaping, the import check, and the preview sandbox each held under every payload listed in "Attacks attempted that failed".

I did find 14 things to fix or to know:

| Severity | Count | What it means here |
|---|---|---|
| blocker | 1 | A hard rule in CLAUDE.md that the repository does not follow. It is a missing record, not a weakness that an attacker can use. |
| major | 3 | Two ways the Studio loses saved work, and one crafted link that stops the Studio's own links from working. |
| minor | 6 | Weaknesses with no working attack today. |
| note | 4 | Facts the owner should know; one is not a security matter. |

The three most important: **SEC-01** (no package check is recorded in `DECISIONS.md`), **SEC-02** (the page-database copy always wins, and the browser copy is then overwritten), **SEC-03** (an unreadable saved project is thrown away by the first edit).

### Words used in this report

- **Payload:** text written to do harm if a program mistakes it for code, for example `<script>alert(1)</script>`.
- **Canary:** a function my test harness plants in every page and frame. If any injected script runs, it calls the canary, and the harness records it.
- **Import check (validator):** `parseProject` in `packages/core/src/engine.ts`. It compares a saved or imported project with the expected shape before the Studio accepts it.
- **Sandbox:** the `sandbox` attribute on a preview frame. It tells the browser to treat the page inside as a stranger: no script, no forms, no popups, no access to the page around it.
- **Fragment:** the part of a web address after `#`. The Studio uses it to remember the current view (`#summary`, `#accent`).
- **Content Security Policy:** a list, written by a page, of what the browser may load or run on that page. It is a second wall behind escaping.
- **Page database:** the document store that the private claude.ai page offers (decision D21). The Studio keeps one document there, `projects/current`, and one copy in the browser's own storage under the key `refraction.project.v1`.
- **Registry, lockfile:** the npm registry is the public store of packages; `package-lock.json` records the exact package files this project installs.

## Attacks attempted that failed

Each item names what I tried and what I saw. "No canary" means no injected script ran anywhere, including inside previews.

1. **Script through the project-name field.** I typed 10 payloads, among them `"><script>__canary('typed')</script>`, `<img src=x onerror=…>`, `' onfocus='…' autofocus x='`, `javascript:…`, `</title><script>alert(1)</script>`, `</style><style>*{display:none}</style>`, `&lt;b&gt; &#x3c;i&#x3e;`, a right-to-left override, 500 letters, and 200 emoji. The field held each one as plain text, cut at 120 characters. The shape of the Studio's page (element names and attribute names) did not change. No canary, no dialog, no request.
2. **Script through "Load a project file".** One file carried a different payload in all 68 text values: the name, the Direction, all 42 content strings (business name, tag, headline, highlighted phrase, lede, both actions, phone, 12 navigation labels, 3 services, 3 facts, about, promise, contact, address, hours, footer), and the Option id, rejected id, reason and time of 6 Decisions. The payloads covered script tags, event-handler attributes, `javascript:` addresses, `</title>` and `</style>` breakouts, CSS (`}*{background:url(…)}`, `@import`, `expression(…)`), frames, forms, `<base>`, `<meta http-equiv=refresh>`, `<object>`, SVG and MathML tricks, HTML entities, template syntax (`{{7*7}}`, `${7*7}`) and replacement patterns (`$&`). I then visited the Directions, all 22 Steps and the Summary, switched on "Dress the Studio…", opened "Closer to this one", and copied the project as text. Result: "Project loaded."; no canary, no dialog, no popup, no request; in the 51 preview documents I inspected, 0 script elements, 0 event-handler attributes, 0 elements that load anything; the Mockup had 142 elements, the same as with harmless text; every one of the 42 content strings appeared in the Mockup **exactly** as written; the Studio's page shape matched the harmless run in all 24 views.
3. **The same file through a tampered `localStorage` record**, read at start. Same result.
4. **The same file through the page database** (simulated; see SEC-02). Same result.
5. **Parser-special characters.** NUL characters inside tags (`<\0script>`), unpaired surrogate halves, right-to-left overrides, zero-width characters, full-width angle brackets, stacked accents, U+2028 and U+2029, and letters that change under lower-casing. No canary. Visible effects only: a right-to-left override reverses how the project name reads, and a highlighted phrase that is half of an emoji splits that emoji.
6. **CSS injection through values.** No project text reaches a `<style>` block or a `style` attribute: tokens come from numbers and fixed lists, and font stacks come from a table in the code (`params.ts:140-156`). I tried to pass strings where numbers or fixed names belong: 340 attempts across all 17 fixed-name fields, in `params` and in Decision values, with payloads such as `x; background:url(//evil.example)` and `x</style><script>…`: all refused. With "Dress the Studio…" on and a hostile project loaded, the Studio's own token rule held one rule, no `url(`, no `@` rule and no `</style>`.
7. **Numbers at the edges.** `1e999` and `-1e999` (which JavaScript reads as infinity) are refused; `NaN`, `Infinity` and `0x10` are not valid JSON; `"8"`, `[8]`, `true`, `null` and an object are refused; `1000` and `999.0000000000001` are refused where 999 is the limit. Accepted edge values: negative zero is written as `0`; tiny values such as `5e-324` reach the CSS as `5e-324px`, which the browser reads correctly (the rest of the stylesheet still applied). 30,000 random accepted projects, with every range sampled at its ends, produced no error, no `NaN`, no `undefined`, and no character outside the expected CSS.
8. **The import check, other attacks.** Unknown keys at three levels are dropped. `__proto__` and `constructor` keys at the top level and inside `decisions` did not change `Object.prototype` (checked after each parse); zod drops a `__proto__` key. 33 type-confusion cases and 8 wrong top-level values were refused. Limits hold: 121-character name, 601-character content string, 13 navigation labels, 13 services, 9 facts, 41 rejected ids, a 61-character key. One oddity: zod counts characters, not storage units, so 61 emoji (122 units) pass as a name. The largest project the check accepts saves as 176,260 characters. In Node, arrays nested 1,000,000 deep and a project with 200,000 Decisions (0.8 seconds) were refused without a crash. In the page, files of 1, 64, 256 and 600 MB were refused in at most 1.7 seconds; the page and the current project survived each time.
9. **The preview frames.** All 34 frames I checked in four views carried `sandbox=""` with no permission words, no `allow` attribute, no `src`; so did every frame in the six views I sampled during each import run. Each preview's address is `about:srcdoc` and its origin is `null`. In the real Mockup, "Send my request" did not submit, links stayed inside the frame, and the frame could not read the Studio (`SecurityError`) or use storage. A hostile document forced into the Studio's own frame ran no script (inline, event handlers, SVG, a `javascript:` frame, a nested frame, a `javascript:` link), could not navigate the top window or the parent, opened no popup, submitted no form (to itself or to the top), started no download, got no autofocus, and its timed redirect was refused. The Studio's title stayed "Refraction Studio". As a control, the same document in a frame **without** the attribute ran its script (two canary calls and one alert), navigated the top window and opened a popup, so the harness does see script when script runs. The one thing the sandbox did not stop is in SEC-07.
10. **The fragment router.** `#<script>alert(1)</script>`, `#javascript:alert(1)`, `#summary?x=1`, `#%73ummary`, `#SUMMARY`, `#nav/../summary`, `##summary`, `#undefined`, `#0` and a fragment of 200,000 letters were all ignored; the Studio rewrote the address to `#directions`. Mid-session, `#constructor` raised one error and navigation kept working (the at-start case is SEC-04).
11. **Code scan of the project's own source.** No `innerHTML`, `outerHTML`, `insertAdjacentHTML`, `dangerouslySetInnerHTML`, `eval`, `new Function`, `document.write`, message listener, `fetch`, `XMLHttpRequest` or `WebSocket`. The only places where a string becomes markup or CSS: `srcDoc` (`preview.tsx:66`, `:106`), a constant `srcdoc` for the start-up probe (`platform.ts:156`; that frame has no sandbox, holds fixed text, and is removed after use), `style.textContent` with engine output (`theme.ts:61`, `:69`), and a download link to an in-memory file (`platform.ts:112`). The address is read once (`store.ts:65`) and rewritten only with fixed names (`store.ts:113`). The built script does contain `innerHTML` and `dangerouslySetInnerHTML` (inside React, unused by this app), one `fetch(` (a Vite helper that acts only if a preload link is added, which never happens), and the code generator in SEC-07.

No cookie, no session storage, no IndexedDB; one `localStorage` key.
